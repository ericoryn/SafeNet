# Результаты фазы 1

Дата: 24 октября 2026 года. Исторический отчёт на момент завершения фазы 1: реализована локальная основа; фаза 2 тогда ещё не начиналась. Последующие возможности описаны в следующих отчётах.

## Что реализовано

- Проект Python 3.11 со структурой `src`, закреплёнными прямыми зависимостями и полным `uv.lock`. Проверки выполнены на Python 3.11.15.
- Общие контракты обезличенного содержимого, текстовых и графических доказательств, сущностей, признаков, трёх независимых оценок, версий, заданий, результатов и решений аналитика.
- Отклонение полей эталонной разметки, даты с часовым поясом, проверка синтетического происхождения, явные переходы состояний заданий и сверка баллов с учётом ограничения диапазона. Незавершённый анализ не получает окончательный результат.
- Проверяемая TOML-конфигурация и семантические отпечатки SHA-256. Начальные пороги не калиброваны; правил детекции в этой фазе ещё нет.
- Начальная SQLite-схема: внешние ключи, версии по материалу, ключи идемпотентности, история решений только с добавлением, запрет изменения сохранённого результата, транзакции.
- Инициализация FastAPI и `/health`; загрузка и анализ тогда ещё не были доступны.
- Оболочка Streamlit с дисклеймером о ручной проверке, явным сообщением о незавершённой детекции и состоянием подключения к API/БД.
- Dockerfile и локальный Compose с отдельными службами API/панели и томом данных API.
- Два вручную подготовленных синтетических OCR-примера, реальное распознавание Tesseract с дедлайном subprocess и загрузчик языковых моделей с проверкой контрольных сумм. Модели загружает оператор; анализ не обращается к сети.

## Проверки

Команда: `.venv\Scripts\python.exe -m pytest -q`. Результат: **80 успешных тестов**, без пропусков и предупреждений. `ruff check .` и `ruff format --check .` пройдены. Предупреждение тестового клиента устранено переходом на поддерживаемую зависимость фреймворка `httpx2`.

Проверены неверные пороги и лимиты, неподдерживаемый OCR, повтор признака и нечисловые значения; отклонение разметки и неверного происхождения; структура доказательств и все 25 переходов заданий; схема SQLite, внешние ключи, несовместимая версия, откат, уникальность версий, запрет привязки чужого результата и изменения истории; безопасные ошибки API и отказ запуска с неверной конфигурацией до создания БД; состояния панели; контроль размера/хеша моделей, повторное использование кэша, дедлайн и реальный OCR обоих примеров.

Живые проверки на момент сдачи:

- `http://127.0.0.1:8000/health`: HTTP 200, схема 1, `detection_ready: false`.
- `http://127.0.0.1:8501/_stcore/health`: HTTP 200.
- Проверка Streamlit средствами тестового фреймворка: исключений и отображённых ошибок нет, подключение подтверждено. Это не проверка отрисовки в браузере или доступности с клавиатуры.

Доказательства: [phase1_runtime.json](phase1_runtime.json). Первоначальный запуск API-тестов блокировался ограничением Windows на внутренний loopback-сокет asyncio; успешная проверка выполнена с разрешённым запуском вне этого ограничения. Обходов в приложение не добавляли.

## Результат OCR

Tesseract 5.5.3, tesserocr 2.12.0, Pillow 13.0.0; профиль `rus+kaz`, только LSTM, один текстовый блок. Закреплены официальные модели `tessdata_fast` 4.1.0.

| Пример | Посимвольная ошибка | Наблюдение |
|---|---:|---|
| Русский | 0,00% | Совпадение после нормализации пробелов и регистра |
| Казахский | 9,71% | Замена Қ/К и потерянные пробелы между отдельными буквами |

Ошибка вычислена расстоянием Левенштейна по нормализованным строкам. Эталоны, распознанные строки, версии и хеши моделей сохранены в [ocr_smoke.json](ocr_smoke.json). Эти два чистых примера подтверждают выполнимость, но не качество на реальных данных и не устойчивость к обфускации. Ошибки казахского примера не исправлялись вручную.

## Запуск и ограничения

Команды установки и запуска: [README.md](../README.md). Процессы API и панели были оставлены на loopback для просмотра; это процессы разработки, а не системные службы. При завершении сеанса их надо запустить заново. В оболочке фазы 1 нет загрузки и скоринга.

Docker отсутствовал: сборка образа, Compose и Linux в рамках этой фазы не проверены. Контракты проверяли структуру, а не маскировали данные; безопасная подготовка относилась к фазе 3. Генерация набора, правила, граф, действия аналитика и измерения производительности оставались последующими этапами. Начальные лимиты и пороги не являются измеренными критериями приёмки.

После сдачи требовалось одобрение фазы 2; оно впоследствии получено.
