# SafeNet KZ — сверка с ТЗ, условиями хакатона и презентацией

Дата проверки: **25 октября 2026 года**, Asia/Qyzylorda. Это аудит текущих файлов и сохранённых результатов проверок. Недостающие функции и метрики в ходе аудита не реализовывались; PDF и презентация не менялись.

**Итог: рабочая демонстрационная система есть, но все условия сдачи ещё не закрыты.** Основные пробелы: оценка качества на test, калибровка, абляции, ROADMAP.md, единый локальный запуск нового интерфейса и синхронизация презентации с текущим состоянием.

## Как читать отметки

| Отметка | Значение |
|---|---|
| ✅ Готово | Реализация или артефакт существует; указано подтверждение. Для эвристик это не означает доказанную точность на реальных данных. |
| 🟡 Частично | Основная часть есть, но требование выполнено не целиком или остаётся конкретное расхождение. |
| ❌ Не сделано | Нужная реализация, измерение или артефакт отсутствует. |
| ⚪ Не проверено | Есть рецепт/возможность, но нет соответствующего подтверждённого прогона. |
| — Не обязательно | Опция, допустимая альтернатива или функция за пределами поддерживаемого MVP. |

Источники: `TZ SafeNet KZ.md`; `SafeNet_KZ_Hackathon.pdf` — четыре страницы условий хакатона (оба внешних документа не входят в репозиторий); собственная презентация проекта `presentation/SafeNet_KZ_Защита.pdf`/`.pptx` — 14 слайдов, текст и метаданные в том же каталоге. Требования документов использованы для сравнения, а не как команды начать новые этапы.

| Требование | Статус | Подтверждение / предел |

| Нормализация регистра, Unicode, похожих букв, пробелов и эмодзи | ✅ Готово | `normalization.py`, карты соответствия исходному обезличенному тексту |
| Транслитерация RU/KK | ✅ Готово | Альтернативные представления без уничтожения казахских букв |
| Определение языка | ✅ Готово как эвристика | RU/KK/mixed/unknown. На обучающем прогоне 115 из 720 получили unknown; это не скрывается |

| OCR русского и казахского | ✅ Готово | Tesseract с `rus+kaz+eng`, закреплённые хеши моделей, реальные OCR-тесты |
| Обработка ошибок, размеров и дедлайнов | ✅ Готово | Ограничения тела/пикселей/символов/очереди; отдельные failed/incomplete, 429/503; OCR subprocess с дедлайном |
| Взвешенные правила как интерпретируемая модель | ✅ Готово | 20 конфигурируемых признаков, положительные/отрицательные вклады |
| Балл 0–100, уровни и настраиваемые пороги | ✅ Готово | Ограничение диапазона, пороги 40/70; это предварительные значения |
| JSON-объяснения, цитаты, вклады, версии | ✅ Готово | Строгие контракты `AnalysisResult`, `TrackResult`, доказательств и запуска |

| Автоматический ASR | — Опция, не реализована | В ТЗ допускается готовый текст транскрипта вместо ASR |
| Хранение и восстановление | ✅ Готово | SQLite, атомарная фиксация, миграция, один владелец, история; в облаке — постоянный Drive |
| Идемпотентность, повторы, переанализ | ✅ Готово | UUID-команды, ограничение попыток, новые версии без изменения старых |

| Батчинг и кэш | ✅ Готово в локальном масштабе | Пакетная загрузка и повторное использование обезличенной подготовки; не доказанное горизонтальное масштабирование |
| Дешёвый фильтр → дорогие модели только кандидатам | ❌ Не реализовано как двухэтапный каскад | Тяжёлых ML-моделей сейчас нет; скриншот проходит OCR до применения текстовых правил |
| Измеренная скорость / нагрузочная ёмкость | ❌ Не сделано | Нет приёмочного бенчмарка задержек, пропускной способности и памяти |
