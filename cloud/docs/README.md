# SafeNet KZ

Облачное приложение с API: [safenet-kz.vercel.app](https://safenet-kz.vercel.app) (вход Vercel). [Развёртывание](DEPLOYMENT.md). Интерфейс: материалы, отдельный граф связей и сводка; работа ведётся в границах ТЗ.

Прототип для аналитика: выявляет признаки, требующие ручной проверки, и не определяет законность материала.

**Готовы:** подготовка и OCR, три трека, объяснения, отдельный граф, API, восстановление, история решений и интерфейс RU/KK. Кнопки «Русский / Қазақша» меняют интерфейс и сохраняют выбор; входные материалы не переводятся. Пороги текущего сайта — 45/55, подобраны на validation. Исторические результаты сохраняют прежнюю конфигурацию.

**Измеренный предел качества:** в повторной синтетической проверке казино имеет recall 33,3% и F1 0,50; исходно были 0 и 0. FPR общей очереди снизился с 11,11% до 6,94%. Повтор открытого test не является независимой оценкой. Система пока не готова к самостоятельному реальному мониторингу. [Метрики](reports/METRICS.md), [полные числа](metrics.json), [чек-лист](CHECKLIST.md), [план внедрения](ROADMAP.md).

[Питч: PDF, PowerPoint и речь на пять минут](presentation/README.md). [Отчёт доработки](reports/PITCH_REVISION.md).

## Запуск из репозитория

Нужны Git, **Python 3.11** и [uv](https://docs.astral.sh/uv/getting-started/installation/) в `PATH`. **Node.js 22 и npm** нужны только для облачной сборки и JavaScript-тестов; локальный сайт запускается без них. При первом запуске требуется интернет для установки закреплённых зависимостей и загрузки трёх моделей OCR. Ключи API и аккаунт Vercel для локальной работы не нужны.

```sh
git clone https://github.com/ericoryn/SafeNet.git
cd SafeNet
python tools/demo.py
```

Если интерпретатор в вашей системе называется `python3`, используйте его вместо `python`. Все дальнейшие команды выполняются из корня репозитория, если явно не указан `cd cloud`.

Команда выполняет `uv sync --frozen --extra ocr`, проверяет модели OCR и запускает сайт с API. На пустой базе создаются шесть синтетических материалов. [Сайт](http://127.0.0.1:8501), [состояние](http://127.0.0.1:8501/backend/health), [API](http://127.0.0.1:8501/backend/docs). Остановка — `Ctrl+C`; база `data/demo.sqlite3` сохраняется. [Сценарий на пять минут](DEMO.md).

Альтернатива: `docker compose up --build`. Новый Compose запускает тот же сайт, API и демо, хранит базу в именованном томе. `docker compose down` том не удаляет. Контейнерный прогон не выполнен: Docker на этой машине отсутствует; однокомандный Python-запуск проверен.

Параметры: `SAFENET_PORT` (по умолчанию 8501), `SAFENET_CONFIG` (для сайта `config/calibrated.toml`), `SAFENET_TESSDATA` (модели `.tools/tessdata`). Для самостоятельного API можно запускать `safenet.api:app`; его базовый конфиг остаётся `config/detector.toml` с историческими 40/70. Один процесс владеет базой; второй владелец отклоняется. Исходные URL не посещаются.

## Оценка и обратная связь

После генерации датасета из раздела ниже `uv run --frozen --extra ocr python tools/evaluate.py --output reports/evaluation-new` готовит validation, выбирает пороги, сохраняет фиксацию и только затем читает test. Существующий первый прогон не перезаписывается. После изменения правил повтор того же test является регрессией, а не новой независимой оценкой. Числа по языкам, матрицы ошибок, precision@K и четыре варианта абляции находятся в `metrics.json`.

`python tools/feedback.py --input export.jsonl --output feedback.jsonl` формирует набор последних решений для последующей разметки и калибровки. Положительное решение требует уточнения треков; оценки автоматически не меняются.

## API и решения аналитика

Форматы загрузок, пагинация, граф, версии и повтор заданий описаны в [API.md](API.md). Каждая команда содержит UUID `request_id`: одинаковый повтор сохраняет идентификаторы, конфликтующее содержимое возвращает 409.

Задания и безопасные метаданные сохраняются сразу; исходные тексты и изображения ожидают подготовки только в ограниченной памяти. После обезличивания SQLite получает подготовленный JSON и реконструированный PNG. Результат, итоговый статус, сводка очереди и новые события графа фиксируются одной транзакцией. Прерывание до подготовки требует повторной передачи источника; сохранённая подготовка возобновляется без OCR. Ошибка не становится успешным нулевым риском.

По умолчанию: HTTP-тело 5 MiB вместе с Base64, 1 000 ожидающих заданий, бюджет исходных данных очереди 32 MiB, один работник, три попытки. Переполнение возвращает 429, недоступность SQLite — 503. Переанализ создаёт новую версию и исключает самовлияние графа. Решения только дополняют историю и не меняют оценки автоматически.

Независимый HTTP-прогон с OCR и принудительным перезапуском:

```sh
uv run --frozen --extra ocr python tools/api_smoke.py --database data/api-demo-v2.sqlite3 --port 8002
```

Укажите несуществующую БД и свободный порт. Проверка сохраняет три типа решений, проверяет идемпотентность и приватность, перезапускает сервер и пишет `reports/phase6_api_smoke.json` и обезличенный экспорт. Сервер проверки в конце останавливается. База измеренного примера — `data/api-demo-v1.sqlite3`; её не перезаписывайте.

## Датасет и подготовка

```sh
uv run --frozen --extra ocr python -m safenet.evaluation.generate --output data/synthetic-v1 --count 1200 --seed 42
```

Создаются 720 обучающих, 240 валидационных и 240 тестовых записей, отдельные входы и эталоны, 400 PNG. Каталог не перезаписывается. Количество — 600–10 000; `--font` задаёт шрифт с русскими и казахскими глифами. По умолчанию: Arial в Windows, DejaVu Sans в Linux. [DATA.md](DATA.md) описывает происхождение, метки и изоляцию выборок. Каталог `data/` игнорируется Git. Структурный отчёт — `reports/dataset_summary.json`. Генерация не загружает материалы в API автоматически.

```sh
uv run --frozen --extra ocr python -m safenet.prepare --input data/synthetic-v1/inputs/train.jsonl --output data/prepared-train-v1 --image-root data/synthetic-v1
```

Выходной каталог не должен существовать; для повтора выберите новый. JSONL/CSV проверяются по размерам, количеству и полям. Пути изображений должны оставаться внутри корня. Поддерживаются только синтетические/уже обезличенные источники; поля эталонных ответов отвергаются.

Успешный материал получает каталог UUID с `prepared.json` и, для изображения, `evidence.png`. Итоги — `outcomes.jsonl` и `summary.json`; любой неуспех даёт ненулевой код завершения. Прерванный запуск может оставить безопасную частичную выдачу, но не перезаписывает прежнюю.

Скриншот сохраняется как реконструкция обезличенного OCR-текста: оригинальные пиксели, метаданные и нераспознанная графика не копируются. OCR работает в подпроцессе с дедлайном; пустое изображение даёт неполный результат. `load_prepared(case_directory, config)` повторно использует подготовку. Смена весов/порогов не требует OCR; несовместимые параметры подготовки, версии движка/моделей или повреждённый PNG отклоняются. Это внутренний формат кэша, а не доверенный формат внешней загрузки.

## Автономный скоринг и граф

```sh
uv run --frozen --extra ocr python -m safenet.score --input data/prepared-train-v1 --output data/scored-train-v1
```

Выход не перезаписывается. Команда читает манифест и обезличенную подготовку без эталонных меток и OCR. Результаты и объяснения — `outcomes.jsonl`, очередь по максимальному баллу — `queue.jsonl`, сводка — `summary.json`. Ошибки остаются отдельными состояниями. При равных баллах порядок задаётся UUID.

Общий движок — `analyze(prepared, config)`. Неподготовленные/устаревшие данные не получают успешного результата. Оценки повторяются при одинаковом входе, настройках и контексте; UUID и время нового анализа отличаются. Без явно переданного графа его вклад нулевой.

```sh
uv run --frozen --extra ocr python -m safenet.score --input data/prepared-train-v1 --output data/graphed-train-v1 --graph-scope train
```

`--graph-scope` включает отдельный индекс `train`, `validation`, `test` или `demo`. Не смешивайте выборки и не открывайте отложенную выборку при разработке. Принадлежность задаёт вызывающий код, а не имя файла.

Материалы соединяются через аккаунты, домены, промокоды, тестовые карты и документированные шаблоны. Хвосты карт и суммы не служат идентификаторами. Редиректы берутся из предоставленных метаданных, без сетевых запросов. Порядок манифеста задаёт доступность контекста: материал использует предшествующий снимок. Источники влияния — только высокие базовые оценки; текущему материалу нужен базовый уровень не ниже среднего. Выбирается наиболее сильная связь, не сумма связей; предел — 15 баллов. Усиленные оценки дальше не распространяются.

`graph.json` содержит узлы, рёбра, снимки и компоненты. Предел обработки — 100 000 узлов/200 000 рёбер: превышение даёт явный неуспех. Просмотр ограничен 100 узлами/200 рёбрами с `total_edges` и `truncated`; это не влияет на расчёт. Программный вызов: `GraphIndex(config, "demo")` и `analyze(..., graph=index, scope="demo")`. Сервис восстанавливает индекс из сохранённых базовых событий, а переанализ не добавляет материал повторно.

## Проверки

Подготовка окружения без запуска сервера и проверки Python:

```sh
uv sync --frozen --extra ocr
uv run --frozen --extra ocr python tools/fetch_ocr_models.py
uv run --frozen --extra ocr python -m pytest -q
uv run --frozen --extra ocr python -m ruff check .
uv run --frozen --extra ocr python -m ruff format --check .
uv run --frozen --extra ocr python tools/ocr_smoke.py
```

Нужны дополнение `ocr` и три модели. Пропуск реального OCR не является полной проверкой. Временные БД находятся в `.cache/pytest`. Ограниченная среда Windows может требовать разрешения на loopback-сокеты даже для тестового клиента API.

Проверки интерфейса, переводов и облачного шлюза при установленном Node.js 22; эти тесты не требуют облачных учётных данных:

```sh
npm --prefix cloud ci
node --test cloud/ui.test.mjs cloud/i18n.test.mjs cloud/gateway.test.mjs
```

Два независимых OCR-примера находятся в `tests/fixtures/ocr/`. Перегенерация:

```sh
uv run --frozen --extra ocr python tools/ocr_smoke.py --generate-fixtures /path/to/font-with-ru-kk.ttf
```

Замените `/path/to/font-with-ru-kk.ttf` на путь к шрифту с русскими и казахскими символами. Для обычного запуска тестов перегенерация не нужна: обе фикстуры уже включены в репозиторий.

Отчёт `reports/ocr_smoke.json` содержит символьную ошибку по расстоянию Левенштейна после нормализации пробелов/регистра. Непустой текст подтверждает работоспособность, но не точность на реальных материалах.

## Границы и документы

Контракты отвергают лишние поля, но сами не обезличивают. Содержимое сохраняется только после `preprocess_record`. Основной движок не зависит от API, интерфейса или хранилища. SQLite использует внешние ключи и короткие транзакции, результаты версионируются, решения только дополняются.

OCR: Tesseract через [tesserocr](https://github.com/sirfz/tesserocr), профиль `rus+kaz+eng`; модели [tessdata_fast 4.1.0](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0) закреплены по SHA-256. Маскирование и язык определяются эвристически и не сертифицируют произвольные приватные данные как обезличенные.

Нет автоматического ASR, обученного классификатора, живого сбора данных или переобучения по кнопкам. Отложенные выборки не использовались для скоринга и настройки. Измеренные количества и синтетические проверки не являются реальной точностью.
