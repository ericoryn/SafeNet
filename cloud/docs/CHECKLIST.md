# SafeNet KZ — актуальный чек-лист по ТЗ и презентации

Обновлено 25.10.2026 после поручения «все сделай» и добавления RU/KK. Источники: `TZ SafeNet KZ.md`, четыре страницы `SafeNet_KZ_Hackathon.pdf`, обновлённая собственная презентация из 12 слайдов. [Первичная подробная сверка](reports/CHECKLIST_INITIAL.md) сохранена как исторический аудит. По последующему поручению «доработай и сделай презу для питча» PDF/PPTX обновлены.

✅ — реализовано и проверено в указанном объёме; 🟡 — есть конкретный предел; ❌ — требование качества не достигнуто; ⚪ — проверка не проводилась; — — необязательная возможность.

**Итог:** функциональный MVP, двуязычный интерфейс и оценочные артефакты готовы. Заявлять полную готовность детектора к реальным данным нельзя: повторный синтетический test показал полноту казино 33,3% и FPR очереди 6,94% (исходно 0% и 11,11%). Это измеренный результат, а не скрытый пункт разработки.

## 5. Данные и оценка — ТЗ 7, 9

| Требование | Статус | Факт |
|---|---|---|
| Не менее ~1000 записей | ✅ | 1200 синтетических записей, 400 изображений, seed 42 |
| Train/validation/test | ✅ | 720/240/240, изолированные семьи/кампании/сущности; эталоны отделены от входа |
| Трудные негативы | ✅ | Бесплатные конкурсы, реклама, новости, учебные материалы и благотворительность |
| Калибровка без test | ✅ | Пороги 45/55 выбраны по validation; фиксация записана до чтения test |
| Precision/recall/F1/FPR | ✅ | По каждому треку, языку и типу источника; `null` при неопределённом знаменателе |
| Матрицы ошибок | ✅ | `[[TN, FP], [FN, TP]]` |
| Precision@K | ✅ | K=10/20/50, детерминированная очередь |
| Абляции | ✅ | Полная модель / без графа / без OCR / без обоих, одинаковые 240 записей |
| Реальное низкое число ложных тревог | ❌ не доказано | Синтетический FPR всей очереди 6,94%; целевой уровень не согласован. Числа по трекам нельзя подменять общей оценкой |
| Производительность | ✅ измерен ограниченный сценарий | [Бенчмарк](reports/evaluation-v3/benchmark.json): локальный последовательный скоринг из кэша и память Python; прежний запуск с OCR сохранён в reports/evaluation; это не облачная нагрузочная ёмкость |
| Двухступенчатая фильтрация | — | Дорогой ML-модели в MVP нет. Добавлять отсев изображений до OCR означало бы терять их текст; расширение описано в ROADMAP |
