# Развёртывание SafeNet KZ на Vercel

## Состав приложения

Текущий демонстрационный проект — `safenet-kz`, регион сервера — `iad1`. Развёртывание включает интерфейс RU/KK, документацию и API через префикс `/backend`. Адрес проверенного развёртывания публикуется в отчёте [CLOUD.md](reports/CLOUD.md). Для собственной копии выберите свой проект и команду Vercel при привязке каталога.

Интерфейс позволяет загрузить текст, готовый транскрипт, изображение, JSONL/CSV; фильтровать очередь; открыть независимые оценки трёх треков и их доказательства; перейти к связанному материалу; просмотреть версии; сохранить одно из трёх решений; запустить переанализ и скачать обезличенный экспорт. Исходники ввода не помещаются в статические файлы.

## Хранение и обработка

Статические файлы обслуживает Vercel. Node.js-функция `cloud/api/gateway.mjs` пересылает запросы в именованный Vercel Sandbox `safenet-runtime`. В нём работает существующий FastAPI/Uvicorn с одним процессом, SQLite и ограниченным фоновым обработчиком. Нативный Tesseract использует закреплённые модели русского, казахского и английского.

SQLite, WAL и ключ шлюза находятся на постоянном Vercel Drive `safenet-data`, смонтированном в `/data`, объёмом **1 GiB**. Файловая система функции не используется для постоянной БД. Drive переживает остановку Sandbox и истечение снимка; снимок Sandbox имеет срок семь дней. При холодном создании зависимости и модели устанавливаются заново, существующая БД подключается с Drive. При обычном возобновлении запускается API и выполняется восстановление фазы 6. Время холодного запуска зависит от облачной инфраструктуры и загрузки моделей.

Одновременно этой базой владеет один сервер. Готовые результаты, обезличенные изображения и решения сохраняются; исходные загрузки в памяти могут потеряться при остановке до подготовки. Такой случай явно требует повторного исходника, а не выдаёт фиктивный результат. Автоматическое масштабирование нескольких SQLite-писателей не предусмотрено.

Документация платформы: [постоянные Sandbox](https://vercel.com/docs/vercel-sandbox), [Vercel Functions](https://vercel.com/docs/functions). Точные возможности SDK закреплены версией `@vercel/sandbox` в `cloud/package-lock.json`.

## Доступ

Предварительное развёртывание должно быть защищено входом Vercel. Доступ ко всем данным общий для допущенных участников проекта: персональные роли, независимые рабочие пространства и внешняя регистрация не реализованы. Не отключайте защиту для произвольных частных загрузок.

Прямой порт Sandbox дополнительно требует `X-SafeNet-Access`. Ключ генерируется сервером, хранится только на Drive, передаётся шлюзом на сервер и не отправляется браузеру, не входит в сборку, документацию, экспорт или журналы. Функция обращается к Sandbox с управляемой учётной записью Vercel OIDC. Локальная `.env.local` и `.vercel` исключены из Git и архива backend.

Облачный шлюз принимает тело до **4 000 000 байт**, включая Base64; локальный API допускает 5 MiB. Длительность функции ограничена 300 секундами; загрузка возвращает 202, далее работу выполняет сервер. Интерфейс опрашивает статусы до 90 секунд, после чего очередь можно обновить. Ограничения очереди/OCR и семантика ошибок: [API.md](API.md).

## Сборка и публикация

Нужны Python 3.11, Node.js 22 с npm и аккаунт Vercel с доступом к используемым Sandbox/Drive. Локальный запуск без облака описан в [README.md](README.md).

Из корня клона `ericoryn/SafeNet` подготовьте **оба** входа облачной сборки: архив backend и копию документации. Затем перейдите в `cloud`, где находятся `package.json` и `vercel.json`:

```sh
python tools/package_cloud.py
python tools/prepare_cloud_docs.py
cd cloud
npm ci
npm run build
node --test ui.test.mjs i18n.test.mjs gateway.test.mjs
```

`package_cloud.py` создаёт `cloud/private/backend.tgz`; `prepare_cloud_docs.py` — `cloud/docs/`; `npm run build` копирует интерфейс и преобразует документацию в `cloud/public/`. Сам по себе `npm run build` не выполняет первые два шага. Архив сервера собирается по разрешённому списку: Python-исходники, конфигурация, lock-файл и загрузчик моделей. Базы, пользовательские материалы, секреты и окружения в него не входят.

При первой публикации выполните из того же каталога `cloud`:

```sh
npx vercel login
npx vercel link
npx vercel deploy
```

В диалоге `link` выберите нужную команду и проект. Локальная привязка `cloud/.vercel/` не входит в репозиторий и после свежего клонирования создаётся заново. Вход CLI и привязка каталога описаны в документации [login](https://vercel.com/docs/cli/login) и [link](https://vercel.com/docs/cli/link).

Команда `deploy` без `--prod` создаёт предварительное развёртывание. Проверяйте интерфейс, `/backend/health` и основные сценарии на выданном адресе; production публикуется отдельной командой `npx vercel deploy --prod` после проверки. [Параметры deploy](https://vercel.com/docs/cli/deploy).

Статическая документация собирается из русских Markdown проекта. JSON/XML/JSONL отчёты копируются как артефакты, кроме журналов серверов. Команды развёртывания не пересоздают и не очищают Drive. Обновление кода уже работающего Sandbox выполняется отдельно и не должно удалять `/data`.

## GitHub и автоматическое развёртывание

Публикация исходников в GitHub не настраивает автоматическое развёртывание Vercel. Привязка локального каталога через CLI также не заменяет настройку Git integration. В текущем `cloud/vercel.json` указан только `npm run build`: для сборки из чистого Git checkout отдельно нужны генерация `backend.tgz` и подготовка `cloud/docs` из корня репозитория. До настройки этих шагов используйте описанный выше путь через CLI. Производные файлы не следует редактировать вместо исходников.

## Практические ограничения

Hobby-квоты вычислений и 1 GiB диска ограничивают длительность демонстрации и объём накопленных PNG/истории; платный тариф автоматически не включается. Перед промышленным использованием нужны роли доступа, резервное копирование и мониторинг заполнения, согласованная политика хранения, проверка реальных данных и измерения нагрузки. Пороги 45/55 подобраны на синтетической validation; баллы не являются вероятностью нарушения, качество на реальном потоке не подтверждено. Исходные пиксели не сохраняются, маскирование эвристическое. Это ограничения готового прототипа, а не подтверждение производственной эксплуатации.
