# SafeNet KZ — API обработки, фаза 6

API предназначен для доверенного локального оператора и синтетических/уже обезличенных данных. Система показывает признаки для ручной проверки; решение принимает аналитик. Значения баллов не являются вероятностями или правовыми выводами.

Стандартный адрес: `http://127.0.0.1:8000`. Swagger: `/docs`, схема: `/openapi.json`. Демонстрационная база фазы 6 — `data/api-demo-v1.sqlite3`; её можно открыть отдельным сервером на порту 8001. Сервер запускается с одним процессом; второй владелец той же базы отклоняется.

На Vercel тот же API доступен через `/backend`: например, `/backend/health`, `/backend/docs`, `/backend/cases`. Предварительное развёртывание защищается входом Vercel; прямой сервер Sandbox требует отдельный ключ, который браузеру не передаётся. Лимит облачного тела — **4 000 000 байт**. SQLite хранится на постоянном Drive. Устройство и границы доступа: [DEPLOYMENT.md](DEPLOYMENT.md).

## Команды и идемпотентность

Каждая команда POST содержит UUID `request_id`; файловая загрузка передаёт его в строке запроса. Повтор с тем же составом полей и значений возвращает прежние идентификаторы. Статус задания в ответе отражает текущее состояние и может измениться. Конфликтующее использование UUID, в том числе для другого типа команды, возвращает 409. В ответах заданий `request_id` — отдельный ключ задания; исходный ключ команды указан в оболочке ответа загрузки.

## JSON-загрузка

```json
{
  "request_id": "b6d7d9f8-31eb-4c47-91e3-320b0d977a85",
  "records": [
    {
      "provenance": "synthetic",
      "synthetic": true,
      "source_kind": "text",
      "text": "Взнос 5000 тг. Победителя определит случайный выбор."
    }
  ]
}
```

`source_kind`: `text`, `transcript` или `screenshot`. `provenance`: `synthetic`/`deidentified`; флаг `synthetic` должен соответствовать происхождению. Можно передать часовой пояс в `created_at`, тестовый UUID `synthetic_account_id` только для синтетических данных и `redirect_chain` из предоставленных URL. Переходы по URL не выполняются.

Скриншот передаётся с пустым `text`, `image_format` из `png`/`jpeg`/`webp` и `image_base64`. Передача исходного имени файла или пути не предусмотрена. Ответ содержит только созданные сервером UUID. Максимум HTTP-тела — **5 MiB вместе с Base64 и JSON**, поэтому допустимые исходные байты изображения меньше 5 MiB. Тип, размеры, число кадров и читаемость проверяет существующий OCR-процессор.

JSONL/CSV используют поля `IncomingRecord`, описанные в `DATA.md` и примерах генератора. Изображения через файловые ссылки в этих маршрутах не открываются: загрузите байты скриншота через JSON-модель. UUID материалов из импортируемого файла заменяются серверными; метаданные тестовых аккаунтов сохраняются. Файл целиком проходит структурную проверку до постановки пакета в очередь. Исходное тело не записывается во временный файл.

## Обработка, повтор и переанализ

Обычный переход: `queued → processing → completed`. Неудачная подготовка приводит к `failed` или `incomplete`; `error_code` объясняет категорию. Для таких заданий итоговый результат и баллы отсутствуют. Основные коды — `invalid_input`, `unsupported_input`, `ocr_failed`, `processing_failed`, `interrupted`.

По умолчанию разрешены **1 000 ожидающих/обрабатываемых заданий**, **32 MiB бюджета исходных данных в очереди**, **один работник** и **три попытки на задание**. Бюджет полезной нагрузки не является измерением общего RSS процесса. Настройки находятся в `[limits]` и `[processing]`. OCR имеет отдельный ограниченный subprocess и дедлайн 20 секунд.

После аварии:

- Если подготовка сохранена, задание возвращается в очередь и использует обезличенный кэш без OCR.
- Если подготовка ещё не сохранена, исходных данных на диске нет: статус — `incomplete / interrupted`.
- При исчерпании попыток автоматического возобновления нет.
- Уже завершённое задание не выполняется повторно и сохраняет прежний результат.

Повтор с сохранённой подготовкой:

```json
{"request_id": "2e0b1e55-b428-49d4-9056-456f369eae6e"}
```

Если сервер отвечает `source_required`, добавьте в этот объект `record` с тем же исходным текстом/изображением и метаданными источника. Смена содержимого возвращает `source_conflict`. UUID материала, артефакта и дата публикации сохраняются из исходного задания. Число попыток увеличивается при захвате работником; новая команда повтора не сбрасывает счётчик. Повтор после более новой версии отклоняется как `job_superseded`.

Для отдельного переанализа отправьте только новый `request_id` в `/cases/{case_id}/reanalyze`. Результат получает новый UUID и возрастающий номер версии. Повтор того же задания сохраняет ранее выделенный номер, поэтому при неуспешных заданиях в истории возможны пропуски версий. Старые результаты не изменяются. Переанализ не добавляет материал в граф второй раз и исключает его собственные голоса из влияния. Изменение весов/порогов может использовать подготовку; несовместимость настроек подготовки/OCR не запускает повторное распознавание реконструкции как оригинала — для нового источника нужна новая загрузка.

## Очередь и граф

`GET /cases`: `limit=1..200`, `cursor`, `track=lottery|casino|investment`, `level=low|medium|high`, `language=ru|kk|mixed|unknown`, `status`, `action`, `since`, `until`. Даты должны содержать часовой пояс.

Сортировка: максимальный балл убывающе, UUID материала возрастающе; материалы без результата имеют `queue_score: null`. Фильтр уровня при указанном треке относится к этому треку, иначе — к максимуму треков. `next_cursor` продолжает запрос с теми же фильтрами; это текущая очередь, а не замороженная копия между страницами.

Поле `preview` содержит не более 160 символов уже обезличенного источника для названия строки интерфейса. Пока подготовка не сохранена, оно пустое. Очередь не загружает полный JSON доказательств или изображения; фрагмент ограничивается SQL-запросом.

При повторной обработке карточка может содержать предыдущий успешный результат и статус нового задания. В `/summary` статусы относятся к последним заданиям, а уровни — к последним сохранённым успешным результатам. Это сохраняет доступ к истории при неудаче новой попытки; ошибка не получает нулевую оценку.

`GET /cases/{case_id}/graph` принимает `result_id` исторической версии и меньшие ограничения `max_nodes`/`max_edges`. По умолчанию максимум 100 узлов/200 рёбер. Ответ сообщает снимок, `total_edges` доступной двухшаговой окрестности и `truncated`; отображение не меняет скоринг. Историческая окрестность включает сам материал и контекст, доступный при соответствующем анализе. Граф сервиса относится только к области `demo`; оценочные выборки с ним не смешиваются.

## Решения и экспорт

```json
{
  "request_id": "54063788-4af0-40cc-838a-49eecc4dab7e",
  "result_id": "UUID сохранённого результата",
  "action": "request_review"
}
```

Допустимые действия: `confirm_signs`, `false_positive`, `request_review`. История только дополняется; результат другой карточки привязать нельзя. Повтор UUID не создаёт вторую запись. Действия не меняют оценки и не запускают обучение.

Экспорт содержит записи `begin`, затем `case`/`result`/`decision`/`job` и завершающую запись `end` с `complete: true` и количествами. Клиент обязан проверить завершающий маркер; отсутствие означает неполный поток. Изображения и внутренние нормализационные карты не включаются; реконструированный PNG доступен отдельным маршрутом. SQLite держит снимок чтения на время экспорта; медленный получатель может задерживать очистку WAL.

## Ответы об ошибках

Ошибка содержит только `error_code` и дисклеймер, без исходного тела, имён загруженных файлов или текста исключения. 409 означает конфликт команды/состояния, 413 — слишком большое тело, 415/422 — неподдерживаемый или некорректный ввод, 429 — заполненную очередь, 503 — временную недоступность БД/артефакта. Для 429/503 передаётся `Retry-After: 1`. Неуспех уже принятого задания читается через `/jobs`, а не превращается в HTTP-ответ с фиктивными баллами.

Персональные роли и разделение данных между участниками не реализованы. Облачное развёртывание предназначено для доверенных участников проекта с защитой входом Vercel. Ограничения маскирования и синтетической оценки описаны в `METHODOLOGY.md`.

## Дополнение: сетевые метаданные и хронология

`UploadRecord` и JSONL принимают необязательный `network` только при `synthetic=true`: `group_id` — UUID, `channel_ids` — до 8 UUID, `audience_ids` — до 32 UUID, `role` — `member`, `organizer` или `curator`. Роль организатора/куратора требует `group_id`. Длина `redirect_chain` ограничена 16. Метаданные не вызывают сетевых запросов. Без этих полей старый формат остаётся действительным.

Ответ графа дополнен `timeline`: даты и UUID материалов из отображаемой окрестности, упорядоченные по дате. Исходные результаты и графовые снимки остаются историческими. Новые результаты имеют `rule_version=2`, чтение версии 1 сохранено. Язык интерфейса не меняет машинные имена полей и входной материал.
